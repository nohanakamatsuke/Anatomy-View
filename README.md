# 人体3D · Anatomy View

骨格・筋肉・臓器を探索する、スマートフォン対応の3D人体ビューア。深いグリーンの画面に実際の人体メッシュを配置し、表示と操作感を重視しています。

## 機能

- BodyParts3D の全2,234メッシュを収録（原典の15分類、探索用の10レイヤー）
- 骨格・筋肉・臓器、動脈・静脈・神経・感覚器・結合組織・生殖器・体表の切り替え／重ね合わせ
- マウス・タッチで回転、ピンチ／スクロールで拡大縮小、2本指で移動
- 実メッシュのタップ選択、フォーカス、単独表示、透過調整
- 正面／背面／側面への補間アニメーション、自動回転
- 主要部位の日本語検索、細部の英語名・原典ID検索
- 矢状面・水平面・前額面の断面クリッピング、システム単位の分離
- 選択部位の非表示／復元、お気に入りの端末内保存
- 出典表記付きPNG画像の書き出し、主要部位の4択クイズ
- PWAのホーム画面追加、読み込み済みレイヤーのオフライン利用

## 起動・検証

Node.js 24。配信に必要な依存ファイルは同梱しているので `npm install` は不要です。

```sh
npm start                 # ポート3000。PORTで変更可能
npm test                  # 形状バッファ、参照整合性、検索、操作判定
npm run build             # dist/ へ静的アプリを出力
PORT=3010 npm start       # 別ポートの例
SERVE_DIST=1 npm start    # ビルド成果物を配信
```

## スマホ

iPhone は Safari の共有 → ホーム画面に追加。Android は Chrome → アプリをインストール。初回はネットワークが必要です。最初に開いたレイヤーを順次キャッシュするため、使用するレイヤーを一度ずつ開くと、それ以降のオフライン利用にも備えられます。ブラウザによるキャッシュ消去後は再取得が必要です。

## 読み込みの高速化（v1.1）

公開用ビルドでは形状の結合、部位索引、表示色の作成を事前に行い、端末で毎回2,234メッシュを組み立て直す処理をなくしています。元の頂点・法線・三角形・部位IDは保持し、表示色は8bitに圧縮しています。

モデルの取得、整合性検証、展開、保存はWeb Workerで行います。一度準備した表示用データはIndexedDBへ保存し、再訪時は圧縮展開と形状の組み立てを省略します。モデルの圧縮ファイルはアプリ本体と別のCache Storageに保存するので、画面の更新だけではモデルを削除しません。HTMLはオンライン時に再確認し、オフラインでは保存済みの画面へ切り替えます。画面と各JSモジュールには同じビルド版を付け、古いHTTPキャッシュとの混在を避けます。旧版のモデルが端末に残っている場合は、整合性を検証して新形式へ移行します。

Workerや保存領域が使えない場合も、ネットワークとメインスレッド処理に切り替えて表示します。初回ダウンロード、GPUへの転送、シェーダー準備は必要で、すべての待ち時間がゼロになるわけではありません。ブラウザのデータ消去・自動削除後は再取得します。

開発用の `npm start` は元形式のモデルも扱えますが、高速化後の公開状態を確認するには `npm run build` の後に `SERVE_DIST=1 npm start` を使ってください。

## 描画・ダウンロード

Three.js 0.186.1 をローカル同梱。システムごとに形状をバッチ化し、GPUで選択色・単独表示を処理します。画面の変更とカメラの減衰中のみ描画し、静止時とバックグラウンドでは描画を休止します。スマホのピクセル比は最大1.5に制限。初回は骨格のみ取得し、それ以外は選んだ時に読み込みます。ビルドは内容のハッシュをService Workerの版に埋め込み、アプリ更新時のキャッシュ切り替えを行います。

圧縮形状の初回ダウンロード量: 骨格約4.6MB、筋肉約10.6MB、臓器約5.5MB。全10レイヤーの圧縮形状は合計約33MBです。別途アプリ・メタデータがあります。実機の描画速度は端末・GPU・発熱状態に依存し、60fpsを保証するものではありません。

## モデルと正確性

BodyParts3D 4.0（成人男性の参照モデル）の実メッシュを利用しています。Human Atlas の軽量化済みデータを10レイヤーへ再梱包し、元の形状と識別子を保持しました。詳細な出典・ライセンス・加工内容は [ATTRIBUTION.md](public/ATTRIBUTION.md) に記載しています。

- BodyParts3D: © The Database Center for Life Science, **CC BY 4.0**
- パッキング・軽量化済みデータ提供: [Human Atlas](https://github.com/ashemag/human-atlas)
- Three.js: MIT、[ライセンス同梱](public/vendor/THREE-LICENSE.txt)

元の最適化済みモデルに含まれる全メッシュを保持しています。ただし原典そのものが、あらゆる組織・変異・性別・病変を網羅するものではありません。臓器レイヤーは探索用の簡易分類で、解剖学上の単一の系を表すものではありません。色は説明用です。日本語訳・説明は主要部位のみで、未翻訳部位は原典の英語名を表示します。すべての人体構造、性別、個体差を網羅していません。**医学的な監修を受けた教材や診断・手術計画ツールではありません。**

## モデルの再生成

`public/models/` は生成済みです。通常のビルドでは再取得しません。`scripts/prepare-models.py` は、Human Atlas の `atlas.json` と展開済み `body-0.bin` ～ `body-14.bin` を入力として、必要なメッシュのみ再梱包します。実行前にスクリプト内の入力先と出典を確認してください。

## 機能の範囲

実装したモデル・機能に課金や機能ロックはありません。既存の Anatomy Learning の資産や有料コンテンツはコピーしていません。製品同士の完全な互換性や優位性を検証したものではありません。

女性モデル、病変モデル、関節・筋収縮アニメーション、筋の起始停止と神経支配の網羅解説、切断面の充填やMRI/CT画像、クラウド同期は含みません。肺は原典の肺内気管支・血管の形状が中心で、肺の外形・肺胞は含まれていません。クイズは日本語の主要部位を対象にした4択です。お気に入りは端末・ブラウザごとの保存で、アカウントは不要です。

## 経穴マップ（v1.2・別メニュー）

画面上部の「解剖」「経穴マップ」で切り替えます。WHOの標準361穴を対象に、日本語の漢字名・読みと国際コードを検索一覧・選択後の情報に併記します（例：合谷 / LI4、足三里 / ST36）。漢字・読み・全角コード・別表記（SJ5→TE5、LV3→LR3、DU20→GV20など）から検索できます。経脈と左右で絞り込み、前後の穴を順に見たり、お気に入りへ保存したりできます。「漢字→コード」「コード→漢字」の練習も利用できます。

リンクに `?mode=acupuncture&point=LI4&side=left` を付けると、その穴から開けます。経穴モードの初回は軽い体表レイヤーのみを読み込み、骨格の取得は「解剖」へ切り替えたときに行います。既存の解剖メニューのデータやお気に入りは維持します。

**WHO提供の3D座標を使った機能ではありません。** 基準はWHO *WHO standard acupuncture point locations in the Western Pacific region*（2008、2009年更新・再版、ISBN 9789290613831）です。日本語表記は日本語版Wikipediaを参照し、別の未監修教育用座標をこのアプリの人体表面へ再投影しています。標準位置の認証・専門家の全件監修は受けていません。体表接触のテストは、医学的な取穴精度のテストではありません。

14経脈361穴のうち、口腔内の齦交（GV28）は顔の外側に置かず、一覧と説明のみとしています。他の360穴は左右または中線で合計669マーカーを表示します。WHO361穴の対象にないGV24+（印堂）などは含みません。施術方法、刺入位置・深度、治療推奨・効能は収録しません。

データの出典・版・各ライセンス・変更内容は [経穴データの出典](public/acupuncture/SOURCES.md) と各レコードの `sources` に記載しています。日本語名・読みの派生データはCC BY-SA 4.0、元の座標種はMIT、人体表面はCC BY 4.0です。WHOの全文・図版は再配布していません。

```sh
npm run bake:acupuncture    # data/acupoint-seeds.jsonから体表へ再投影
npm test                    # 361コード・名称・左右・表面接触などを含む
npm run build
npm run test:acupuncture    # スマホ・コード検索・クイズ・オフライン・メニュー復帰
```

ブラウザ検証用の準備は `test:browser` と同じです。スマートフォン実機での検証や専門家による経穴位置の審査は別途必要です。


## スマホの表示改善（v1.3）

初期表示の説明カード・キャッチコピーをなくし、未選択時は人体を広く表示します。経穴の漢字名・国際コードは選択時のみ画面下にまとめ、人体の上に同じラベルを重ねません。部位・経穴の情報はコンパクトなカードにし、説明・お気に入り・出典は「詳細」から開きます。詳細を開いた際に選択位置がカードへ隠れる場合は、カメラを移動して見える位置へ寄せます。

表示方向・透過・拡大縮小・断面などは上部の「表示」へまとめました。「全身」で視点を戻せます。スマホの操作領域は主要ボタンで44px以上とし、下端のセーフエリア、320px幅・横向き表示、入力時の自動拡大を考慮しています。

`npm run test:design` はChromiumのスマホ表示で、初期カード非表示、選択後の要約と詳細の開閉、タップ領域、320/390/430px幅・横向きの表示、表示調整を確認します。実機での検証は未実施です。
